## 输入参数

| 参数 | 含义 | 示例假设 |
| --- | --- | --- |
| λ | 准入帖子/秒 | 10 |
| p | 审核通过比例 | 0.90 |
| N | 每帖进入决策的平均分身数 | 4 |
| c | 选择评论的比例，组合动作也计入 | 0.40 |
| r_d / r_c | 决策/评论平均调用次数，含重试 | 1.10 / 1.10 |
| S_d / S_c | 决策/评论平均服务秒数 | 0.8 / 1.5 |
| t_d / t_c | 每次决策/评论平均总 token | 800 / 1,200 |

决策请求率 `R_d = λ × p × N × r_d`，评论请求率 `R_c = λ × p × N × c × r_c`。示例得到 `39.6` 和 `15.84` 次/秒；平均在途量约为 `31.68` 和 `23.76`。这只覆盖两个生成阶段，审核、理解、embedding 和媒体处理须另外计入。

同供应商 RPM 至少覆盖 `60 × ΣR_i`，TPM 覆盖 `60 × Σ(R_i × t_i)`，并满足其并发限制。示例两个阶段约需 `3,326.4 RPM` 和 `3,041,280 TPM`。配置安全余量并实测长尾；均值公式无法给出 P99。

## 费用模型

按阶段分别记录输入/输出 token 和单价：

`每日模型费用 = 86,400 × Σ R_i × (Tin_i × Pin_i + Tout_i × Pout_i) / 1,000,000`

这里 `Pin/Pout` 是每百万 token 的实际合同单价。未填单价时仅输出 token 需求，不输出货币总额。媒体按分钟/图片/像素计费的供应商需添加相应项；数据库、对象存储、网络及索引费用单列。

预算预留使用每次可独立收费调用的最坏允许费用。UNKNOWN 保留预留，替代调用需要新增预留；把失败重试当作免费会低估成本。单位有效评论费用使用所有处理支出除以成功评论数，同时报告被拒绝、失败和忽略的成本。

## 积压与敏感性

当处理能力 μ 大于到达率 λ 时，积压 B 的理想清空时间为 `B / (μ - λ)`，两者须使用同一种工作量单位。模型故障后的重试与新任务共同消耗 μ。

- N 从 4 提升到 8，决策和评论的模型请求量近似翻倍。
- 平均调用次数由 1.1 升至 2，相关模型负载增加约 82%。
- 评论选择率从 0.4 升到 0.8，评论生成负载翻倍，决策负载不变。
- 点赞与评论可组合；点赞不必增加一次评论生成调用，但会增加独立写入和事件。

视频按分钟、帧量和分辨率分别建模。向量容量按实体数 × 分块数 × 维度 × 每维字节估算原始向量，再计 payload、索引、副本和迁移双份空间。本地模拟器的内存扫描不代表 Qdrant 容量。

## 可复算的费用情景

提供 [成本计算器](../scripts/capacity_cost.py)，必须显式传入输入、输出单价。例如采用**纯假设价格**：每百万输入 token 为 0.5 USD、每百万输出 token 为 2 USD，决策每次 600 输入/200 输出 token，评论每次 900 输入/300 输出 token：

```sh
python3 scripts/capacity_cost.py --input-price 0.5 --output-price 2 --output reports/cost-scenario.json
```

在上表 10 帖/秒且全天持续的假设下，两个阶段合计约 3,832.01 USD/日、114,960.38 USD/30 日。此数值不是实际支出或任何供应商报价；审核、理解、embedding、媒体、数据库、网络和存储尚未计入。流量只持续每日 2 小时时，这两阶段变动费用约为全天值的 1/12；固定基础设施成本另计。原始输入与分阶段结果见 [情景报告](../reports/cost-scenario.json)。接入真实模型后，应以合同单价和采样 token 分布替换假设，再评估候选上限和评论比例。
