# 幻境 HuanJing：多模态帖子与 AI 分身互动

这个项目用 Go、SQLite 持久任务和事务 outbox，实现发帖、真实模型文本理解、公开画像语义评分、模型评论生成、分身动作计划及点赞/评论。文本理解和候选召回默认调用环境变量配置的模型 API；评论生成同样调用真实模型；审核和动作决策仍为模拟实现。

**这是本地原型。** [生产设计](docs/design.md) 中的 Temporal、PostgreSQL、Qdrant 和 MQ 尚未接入。图像、音频、视频可作为附件提交，模型目前只读取文字及用户提供的 caption，尚未处理原始图片、音频、视频，也没有真实安全审核。

## 启动

需要 Go（版本见 `go.mod`），在仓库目录运行。获取项目：

```sh
git clone https://github.com/ayaeum/HuanJing.git
cd HuanJing
```

先按 [.env.example](.env.example) 在运行环境配置 `AI_BASE_URL`（包含 API 前缀，例如 `/v1`）、`AI_API_KEY` 和 `AI_MODEL`，然后启动：

```sh
go run ./cmd/server
```

默认 `AI_MODE=real`；缺少配置时启动失败。端点和凭据只从环境变量读取，不写入源码、数据库或报告。服务本身不自动加载 `.env` 文件。详细协议、配置与未知结果处理见 [真实语义接入](docs/real-semantics.md)。

默认地址 `http://127.0.0.1:8080`，数据库 `data/system.db`，worker 数量 4。可配置 `ADDR`、`DB_PATH`、`WORKERS`、`WEB_DIR` 和 `SEED_TENANTS`。默认只有 demo 租户包含预置分身；使用独立压测租户时启动为 `SEED_TENANTS=demo,loadtest go run ./cmd/server`。详细接口及故障参数见 [API 契约](docs/api-contract.md)。

也可以运行 `docker compose up --build`；容器数据保存在命名卷中，宿主机端口绑定本地回环地址。`docker compose down` 保留数据卷，带 `-v` 则删除演示数据。

浏览器打开根路径即可使用中文演示页面，无需前端构建。自动演示需要 Python 3：

```sh
python3 scripts/demo.py --base-url http://127.0.0.1:8080 --output data/demo-report.json
```

脚本覆盖文字、图片、音频、视频；媒体是测试图、正弦波等材料，模型接收 caption 文本。真实模式会产生外部请求与用量；完整确定性故障演示请在独立服务上显式使用 `AI_MODE=test_fixture`。

`X-Tenant-ID` 是演示租户隔离参数，缺省为 `demo`。客户端可以自选该参数，**它不是身份认证**。不要将服务开放到公网，也不要上传真实私密材料。

## 演示路径

1. 浏览预置分身，提交文字或带 caption 的媒体附件。
2. 查看审核、理解、召回、决策和发布阶段，以及每个分身的匹配依据。
3. 观察动作集合：忽略、点赞、评论、点赞并评论。点赞与评论分别去重，评论失败可以保留成功点赞。
4. 通过故障选项演示退避重试、失败、评论拒绝和未知结果对账。
5. 处理期间停止并重新启动进程，使用同一数据库观察任务恢复。

## 能力与边界

| 环节 | 本地实现范围 | 生产仍需补齐 |
| --- | --- | --- |
| 持久执行 | SQLite 任务及阶段账本、租约、重试 | 分布式编排、数据库高可用、灾备演练 |
| 多模态 | 文件上传、真实模型读取 caption 文字 | 安全解码、真实媒体理解与覆盖审核 |
| 文本理解与召回 | 真实模型摘要/意图/主题 + 全量公开画像语义评分 | 大规模向量检索、质量评测、模型版本治理 |
| 分身决策与评论 | 确定性动作与真实模型公开人设评论 | 真实个性化决策及隐私安全评测 |
| 互动 | SQLite 权威互动、逐动作去重 | 外部发布的幂等、查询和撤回契约 |
| UNKNOWN | 真实请求保留未知状态、显式放弃后才允许重新请求；模拟调用单独对账 | 真实供应商查询、账单与退款对账 |
| 预算 | 发送前预留请求额度，保存实际响应报告的 token | 货币计价、账单对账及全局额度 |
| 权限 | 演示租户字段与分身停用 | 认证、RBAC、审计及数据合规 |

本地数据库连接池只有一个连接，以串行事务实现发布和撤回的竞争控制。当前五个画像全部进入真实模型评分，最多支持 50 个启用画像；按相关性阈值筛选、按分数排序，不走词表或字符哈希兜底。模型请求只包含帖子、分析及当前租户公开画像。私有记忆仍只用于模拟决策的来源校验，未交给模型。

旧确定性实现隔离在 `fixture_matching.go`，仅显式 `AI_MODE=test_fixture` 用于离线工作流测试。运行模式及每个任务的阶段来源会分别显示；历史 Mock 结果保持原标识。

生产方案中的完整跨来源授权闭包、成本加权公平调度、供应商 RPM/TPM、分身冷却与细分动作额度、复杂模型迁移等仍需实现。生产能力须以实际代码和测试为准，不能从设计文档推断已经交付。

接入真实模型之前的历史 Mock 基线：100 帖/8 并发与 200 帖/32 并发全部完成，每条纯跑步帖只有 1 个候选。完成吞吐分别为 9.896、9.908 帖/秒，端到端 P95 为 831.080、3,313.161 ms，最终 outbox 均为 0。见 [100 帖报告](reports/load-relevance-100-c8.json)、[200 帖报告](reports/load-relevance-200-c32.json)。旧版 4 候选报告保留为历史记录，两者工作量不同。

真实语义 8 个样例和 2 个浏览器发布场景通过，协议异常验证 32 例、原有离线工作流 75 例通过。详见 [真实语义接入与证据](docs/real-semantics.md)。历史 Mock 端到端报告见 [此前 E2E 验证](docs/e2e-validation.md)。运行 `make test-e2e` 可重跑独立数据库上的接口与生命周期测试；真实浏览器操作见报告中的运行方法。


## 完成情况与后续计划

可运行源码、媒体样例、中文界面、故障演示、压测工具与原始结果、容量成本模型、容器配置和运维说明已交付。逐项验收见 [交付核对](docs/delivery-checklist.md)，本地组件替换见 [架构说明](docs/local-architecture.md)。

文本理解/候选评分已接真实 API；后续生产工作：

1. 接入真实身份认证、媒体处理、审核、个性化决策模型，校准覆盖与输出质量。
2. 在 PostgreSQL / Temporal / Qdrant 上替换本地实现，保留现有业务身份、动作幂等与恢复回归。
3. 增加供应商 RPM/TPM、成本加权公平调度、动作额度及完整来源授权闭包。
4. 用真实媒体分布和供应商配额重新压测，冻结 SLO，完成高可用与灾备演练。

CI 配置见 [GitHub Actions 模板](ci/github-actions.yml.example)。当前推送凭据只有 repo 范围，没有 workflow 写权限，因此模板尚未放入 `.github/workflows/`，未运行远端 CI。具备权限后将其复制到 `.github/workflows/ci.yml` 即可启用；本次交付证据来自实际本地与容器验证。

评论生成已接入真实模型：按分身公开人设回应帖子，成功结果持久缓存，失败与未知结果保留已有点赞。最新验证见 [真实评论样例](reports/e2e-comments-live.json) 和 [34 项协议及恢复测试](reports/e2e-ai-comments-protocol.json)。历史模板评论保留，新帖使用真实生成。
